## 业务契约

- 页面通过 `/api/v1/missions` 获取唯一演示任务，集中生成业务 API 前缀；当前任务 ID 为 `P-20261001-03`。通过 `/api/v1/assets` 将 `pointId` 精确映射到 `assetId`；目录仅含 A-01、B-08、B-09、B-11、B-12、C-06、D-10，缺失点位禁止写入或绑定其他设施。
- POST findings 必须提供有效 `assetId`、非空 `source` 和 1–300 字 `note`。可选 `requestId` 为 1–120 字字符串，保存于记录；相同键和规范化内容重试返回原记录 `200`，首次新增 `201`，相同键不同内容返回 `409 IDEMPOTENCY_CONFLICT`。旧请求不传键仍兼容，但没有跨请求去重保证。
- PATCH findings 使用 `finding.id`，`status` 只接受 `acknowledged`（已知悉）或 `reviewed`（已复核）；初始 `pending` 为待确认。可选 `expectedStatus` 接受这三种状态，过时状态返回 `409 STATUS_CONFLICT`，已复核记录不能退回。状态未变不会重复创建事件。
- POST rechecks 使用有效 `assetId`，按设施去重，首次返回 `201`，重复返回 `409 RECHECK_EXISTS`；DELETE 使用 `recheck.id`，成功 `204`，记录不存在 `404`。加入复查队列只保存业务记录，不下发机器人任务。
- GET events 读取服务端事件；新增疑点/状态事件含 `findingId/assetId`，复查事件含 `recheckId/assetId`。本地设备操作演示单独展示，不是设备回执，也不进入服务端导出。
- GET export 返回当前保存的 `findings/rechecks/events`、任务、演示标签和导出时间。页面将该响应下载为 `Atomori-本机业务记录.json`，不使用浏览器数组或 localStorage 替代后端存储。
- 页面 API 层统一处理 JSON、HTTP 错误和超时；写入期间禁用重复操作，失败保留备注。同一份输入重试沿用 `requestId`，修改备注后生成新键。服务端写入确认后才显示保存成功；加载失败明确标注，不把样本当作新保存记录。

## 下视持续图传与真实遥测（2026-10-08）

断流根因：旧代理给 MJPEG 使用 `AbortSignal.timeout(8000)`，收到响应头后计时仍在，实测 8.013 秒被取消；直接树莓派流同期持续超过 12 秒。现在 MJPEG 只对连接等待设 8 秒超时，响应期间持续转发；有限 JSON 请求仍有 2.5 秒总超时。
