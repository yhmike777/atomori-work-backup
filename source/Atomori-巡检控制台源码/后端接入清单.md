## 已接入的本机业务记录

- 同源静态页面服务和 `/api/v1/health`。
- 场站、7 个示例设施、1 个演示任务、4 个未配置设备的只读 API。设施目录明确标记 `catalogComplete: false`。
- 疑点新增/知悉/复核、复查加入/取消、事件查询、服务端记录导出均已接入页面，保存在 `backend/data/records.json`（可用 `ATOMORI_DATA_FILE` 修改）。这是**演示任务下的本机业务记录**，不是生产数据库。
- `marp/api.js` 统一 JSON、HTTP 错误和超时；`records.js` 统一数据更新与渲染，`console.js` 负责交互，`live.js` 只负责上游只读数据。没有使用 localStorage 代替持久化。
- 任务 ID 从 `/api/v1/missions` 加载并集中生成接口前缀；点位通过 `/api/v1/assets` 精确匹配，B-10 等目录缺失点位禁止绑定其他设施。加载中、空列表、失败和过时快照明确显示；失败时不宣称保存成功。
- 标记疑点按有效 `assetId/source/note` 提交，保存期间禁用重复点击，失败保留输入；后台确认成功后关闭弹窗。备注安全渲染。
- POST findings 可选 `requestId` 持久去重：新增 `201`，同键同规范化内容 `200`，同键异内容 `409 IDEMPOTENCY_CONFLICT`。同输入失败重试沿用键，修改输入生成新键；未传键保留旧调用兼容。
- PATCH findings 可选 `expectedStatus`，过时状态 `409 STATUS_CONFLICT`；`pending/acknowledged/reviewed` 对应待确认/已知悉/已复核，已复核不能退回。操作使用 `finding.id`，不依赖数组下标或首条记录。
- 复查按 `assetId` 去重（重复 `409 RECHECK_EXISTS`），取消使用 `recheck.id`（成功 `204`）。加入队列只保存业务记录，不下发机器人任务。
- 服务端事件包含 `findingId/assetId/recheckId` 关联，演示种子与本机业务事件明确标注；本地设备操作演示单独分区，不显示为真实设备回执，也不加入服务端导出。
- 气体采样保存保持禁用；仪表和声学仅可添加人工备注，读数、频谱、热像和历史样本不保存为真实测量或证据图片。
- 上游配置后提供只读遥测和图传代理；测量模型仍未接入，真实控制 `POST /api/v1/commands` 保持 `503`，只读模式设备按钮保持禁用。

## 建议的数据契约

实时数据至少包含 `deviceId`、`observedAt`（设备采样时间）、`receivedAt`（服务端接收时间）、`source`（真实设备或演示）、`quality`（有效/过期/失效）、数值与单位。地图数据还需坐标系、地图版本；告警需阈值版本和证据帧 ID。前端应根据 `source` 和 `quality` 显示真实、演示、离线或过期状态，不能仅凭成功 HTTP 响应显示“在线”。

设备命令建议包含 `commandId`、`missionId`、`deviceId`、`action`、参数、操作者、控制权令牌、请求时间；结果区分“服务端受理”“设备侧确认”“执行完成/失败”。保护停止必须遵循设备侧安全链路与独立急停设计，不能把网页请求当成物理急停。

## 推荐接入顺序

1. 导入完整设施/地图/任务主数据，确定设备 ID、点位 ID、坐标系和时间基准。
2. 接入只读遥测、视频和测量数据，先验证采样时间、质量和断线状态。
3. 本轮页面疑点、复查、事件和导出已完成 API 接入；下一阶段按部署需求补账号/权限、操作者与证据引用，不将本机记录当作生产审计系统。
4. 在控制权、联锁、设备回执、超时及独立安全链路完成后，再开放真实控制接口。
